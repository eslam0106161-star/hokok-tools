# خط الأنابيب السحابي: من PDF إلى شرح وأسئلة أكاديمية

يشتغل بالكامل على سيرفرات GitHub (مجانًا، بلا حدود لأن الريبو Public) — تقفل موبايلك تمامًا وهو شغال.

## الإعداد (مرة واحدة بس)

1. **أضف مفتاح/مفاتيح Gemini API كـ Secret**، مش كإدخال عادي:
   - من صفحة الريبو على GitHub → **Settings** → **Secrets and variables** → **Actions**
   - اضغط **New repository secret**
   - **Name**: `GEMINI_API_KEYS`
   - **Value**: مفتاحك، أو أكتر من مفتاح مفصولين بفاصلة بدون مسافات، مثال:
     ```
     AIzaSy...key1,AIzaSy...key2
     ```
   - احفظ

## طريقة الاستخدام (كل مرة)

1. ارفع ملف الـ PDF بتاع الكتاب داخل مجلد `input/` في الريبو (استبدل أي ملف قديم فيه، أو ضيف كذا ملف مرة واحدة لو حابب يتعالجوا كلهم في نفس التشغيلة)
2. من تبويب **Actions** في الريبو، اختار الـ workflow اسمه **"توليد شرح وأسئلة من كتاب PDF"**
3. اضغط **Run workflow**، واختار الإعدادات (النموذج، طول الشرح، عدد الأسئلة...) أو سيبها الافتراضية
4. اضغط **Run workflow** الأخضر
5. **اقفل الموبايل عادي، مفيش داعي تستنى** — هيشتغل في الخلفية على سيرفرات GitHub
6. لما يخلص (هتوصلك حالته من نفس الصفحة، أو افتحها بعدين)، هتلاقي **Artifacts** تحت — حمّل `book-output-...` وهتلاقي جواه:
   - ملف `Word` جاهز فيه الشرح والأسئلة
   - ملف `.txt` بالنص الخام المستخرج (احتياطي)

## أنواع الأسئلة

لكل جزء من الكتاب، بيتولّد 3 أنواع أسئلة مستقلة:
- **اختيار من متعدد**: عدد الخيارات متغيّر (2 أو 3 أو 4) حسب طبيعة السؤال، مش ثابت دايمًا على 4.
- **مقالية**: بأسلوب امتحانات كليات الحقوق المصرية الفعلي (عرّف/اذكر/بيّن/ناقش/قارن).
- **صح وخطأ**: عبارات دقيقة قابلة للحكم عليها بشكل قاطع، بنفس دقة صياغة الامتحانات الحقيقية.

عدد كل نوع قابل للتحكم من واجهة الـ workflow (`mcq_count`, `essay_count`, `tf_count`) — سيب `tf_count` على `0` لو مش عايز أسئلة صح/خطأ خالص.

الشرح نفسه بيتكتب بالعربية فقط (حتى لو النص الأصلي فيه مصطلح أجنبي جنب العربي)، وبيحافظ على بنية أي تعداد موجود في النص الأصلي (أ/ب/ج أو أولاً/ثانياً)، وبيتضمن أحيانًا ملاحظة توضيح عامية مميّزة بخط مائل بالصيغة "💡 خد بالك: ..." عند النقط اللي محتاجة تبسيط.

- **تصنيف ذكي للهيكل** (`verify_structure`): بعد جمع كل عناوين الكتاب، بيتبعت استدعاء واحد رخيص لكل كتاب كامل (نص العناوين بس، مش المحتوى) لـ Gemini، يراجع فيه مستوى العناوين "الغامضة" بس (أولاً/ثانياً، أو عنوان مكتشف بصريًا بعلامة [HEADING]) بناءً على فهمه للسياق الكامل للكتاب — بدل الاعتماد على تخمين محلي بسيط (عمق واحد أعمق من آخر عنوان مؤكد). العناوين المؤكدة (باب/فصل/مبحث بكلمة صريحة) محمية تمامًا ولا تتغير حتى لو النموذج حاول تعديلها.

## مراحل التحقق (Verification)

بالإضافة لمرحلتي الاستخراج والتوليد، فيه مرحلتا تحقق اختياريتان (مفعّلتان افتراضيًا):

- **مراجعة الاستخراج** (`verify_extraction`): كل صفحة بعد استخراج نصها، بيرجع النموذج يقارن النص بالصورة تاني بالتركيز على الأرقام (أرقام مواد، تواريخ، نسب) وأسماء الأعلام، ويصحح فقط أخطاء القراءة دون إضافة أو حذف.
- **مراجعة المحتوى** (`verify_content`): بعد توليد الشرح والأسئلة لكل جزء، بيرجع النموذج يراجعها مقابل نص الجزء الأصلي فقط، ويتحقق من: عدم وجود معلومة "مؤلَّفة" غير موجودة بالنص، مطابقة كل رقم للنص الأصلي حرفيًا، صحة الإجابة الصحيحة في كل سؤال اختيار من متعدد فعليًا، وقابلية كل سؤال مقالي للإجابة من هذا الجزء وحده.

كمان، عند توليد كل جزء، بيتبعت للنموذج ملخص مختصر جدًا لعنوان الجزء السابق (وآخر ما اتكتب فيه) وعنوان الجزء التالي — لتقليل أثر تقطيع الكتاب لأجزاء منفصلة (تكرار الشرح أو تناقض بين جزأين متتاليين)، مع التأكيد على النموذج إن ده للسياق فقط مش مصدر معلومات.

**التأثير على الوقت/التكلفة**: تفعيل المرحلتين بيضاعف تقريبًا عدد استدعاءات Gemini (استدعاء إضافي لكل صفحة، واستدعاء إضافي لكل جزء)، يعني وقت التشغيل الكلي وحصة الـ API المستهلكة تتضاعف تقريبًا. لو الكتاب كبير جدًا أو حصة المفاتيح ضيقة، ممكن تقفل أي مرحلة منهم لـ `no` عند تشغيل الـ workflow.

**تقرير التحقق**: كل تشغيلة بتنتج ملف `{اسم-الكتاب}-تقرير-التحقق.txt` جوه الـ Artifacts، فيه إحصائية عدد الصفحات/الأجزاء اللي اتصححت فعليًا، وتفاصيل كل تصحيح تم عمله — راجعه لو حابب تتأكد بنفسك من نوعية التصحيحات.

## ملاحظات مهمة

- **صيغة العناوين المدعومة**: يدعم السكربت صيغتين للعنوان (يقدر يتعامل مع الاثنين حتى لو اتخلطوا في نفس الكتاب):
  1. عنوان منفصل في سطر لوحده، والعنوان الوصفي في السطر اللي بعده مباشرة: `الباب الأول` ثم `نشأة القانون الدولي` في السطر التالي.
  2. عنوان مدمج في نفس السطر بفاصل نقطتين أو شرطة: `الباب الأول: نشأة القانون الدولي` أو `الفصل الثاني - المسؤولية الدولية`.
  المستويات المدعومة بالترتيب: القسم، الباب، الفصل، المبحث، المطلب — بأرقام ترتيبية مكتوبة بالحروف (الأول، الثاني... حتى العشرون)، مش أرقام رقمية (١، ٢) ولا حروف إنجليزية.
- **الحد الأقصى لوقت التشغيل**: 6 ساعات (قيد من GitHub نفسه) — مع تفعيل مرحلتي التحقق، الوقت المستهلك تقريبًا الضعف، فكتاب كبير قد يحتاج تقفل مرحلة أو أكتر من التحقق لو قارب على الحد الأقصى
- لو حصل خطأ أو توقف نفاد مفاتيح، شوف الـ Logs من نفس صفحة الـ run لمعرفة السبب بالتفصيل
